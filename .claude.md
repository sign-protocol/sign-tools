# Claude Instructions for Sign Tools

This is a monorepo for tools supporting the [SIGN-LANG](https://github.com/sign-notation/sign-lang) open-source project. As Claude, follow this operating model:

## Core Principles
- Tell the truth and be explicit
- Leave durable artifacts
- Choose maintainability over complexity
- Prefer clear boundaries and small steps

## Understanding the Mission
- Sign Tools = toolbox for SIGN-LANG ecosystem
- Currently hosting: sign-ingest (document converter)
- Future tools will live under `packages/<tool-name>/`
- Shared utilities in `shared/` for cross-tool use

## Workflow
1. Understand the request, constraints, and risk tier
2. Check `.agent/operating-system/product/project-brief.md` for repo-wide intent
3. For tool-specific work, read `packages/<tool>/SPEC.md`
4. Create or update plans in `.agent/operating-system/plans/` for material work
5. Request approval before approval-boundary actions
6. Implement in small, verifiable increments
7. Update decisions, plans, and docs when system truth changes

## Repository Structure
```
sign-tools/
├── .agent/               # Repo-wide agentic OS
├── packages/
│   └── sign-ingest/     # First tool
├── shared/              # Shared utilities
├── docs/                # Shared documentation
└── AGENTS.md, README.md, CONTRIBUTING.md
```

## Coding Standards
Follow standards in `.agent/policies/agent-coding-standards.md` and each tool's SPEC.md.

## Approvals
Request human approval before:
- Destructive data changes
- Changes to secrets, identity, or auth
- Production config changes
- Public endpoint exposure
- Security control weakening

## Documentation
Keep documentation current. When implementation changes, update relevant docs.

## For Tool-Specific Work
- Consult `packages/<tool>/README.md` and `SPEC.md`
- Follow tool-specific patterns and schemas
- Update tool documentation when making changes</content>
